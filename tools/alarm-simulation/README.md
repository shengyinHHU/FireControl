# 模拟报警

在“消防警情记录”的“查询”旁点击“模拟报警”，选择传输装置或119来源、演示场所并填写内容。默认生成后进入指挥大屏，显示带“模拟演示”标记的警情及对应地图点位，并启动声光提醒。已有大屏也会通过实时通知或3秒轮询看到新警情。浏览器若拦截声音，点击“开启报警声音”。

演示场所必须是当前用户可访问、具有有效GCJ-02坐标且位于大厂范围内的已有场所；不提供随意伪造地图位置的入口。没有可用场所时，先维护场所坐标。

在警情详情填写处理说明并“确认处理”，模拟警情从大屏警情、地图及传输装置历史中移除，记录页保留处理结果供查阅。其他尚未确认的新警情继续提醒。“停止本次报警”只停止当前声光提醒，不代替处理。

## 部署

1. 备份后执行 `SQL/fire_alarm_simulation.sql`。脚本可重复执行，只建立独立模拟表和操作权限，不生成模拟数据、不授予普通角色权限。
2. 发布并重启新版后端，再发布匹配的前端。新统一查询引用模拟表，因此需先执行SQL。
3. 超级管理员默认可用；为需要演示的普通角色配置 `fire:alarms:simulate`，同时保留 `fire:alarms:list`、`fire:places:list`及相应数据范围；进入大屏还需已有的 `fire:dashboard:list` 权限。重新登录刷新权限。
4. 在有权限的账号下演示两种来源，检查列表、地图、声音、边框和处理后的同步移除。

模拟记录独立存储，具有创建人、部门、场所坐标和时间快照；相同创建请求重试只生成一条，重复处理保留第一次处理结果。不会写入真实设备报文、设备事件或119接入表，也不会向外部设备或119平台发送警情。设备接入统计和119同步统计保持真实数据口径。

## 验证

- `python tools/alarm-simulation/verify_project.py`：临时MySQL中验证真实MyBatis查询、数据范围、坐标、幂等、处理、事务和提交后通知，不访问业务数据库。
- `node tests/fire/alarm-simulation.browser.cjs`：前端目录运行；需要Playwright，可通过`PLAYWRIGHT_PATH`指定运行时包。使用受控HTTP和地图厂商接口，运行真实Vue组件、地图适配器和上传WAV播放。
- `npm run test:fire`、`npm run build:prod`以及后端Maven编译。
