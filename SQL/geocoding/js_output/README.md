# 本次 JS API 批量定位结果

已使用之前实测成功的官方 JS API 示例及现有 Key，处理全部 101 家机构。地址查询复用相同地址缓存，累计 156 次成功查询（含地址解析与 68 次补充名称搜索），无接口错误。临时浏览器与本地服务已关闭，没有连接业务数据库。

## 交付文件

- update_coordinates.sql：70 家机构的候选坐标更新，审查后手动执行。
- 机构坐标审查清单.csv：101 家机构，一家一行；包含原始地址、建议坐标、匹配地址、判断依据。
- 需人工核对的机构.csv：剩余 31 家，地址不完整、名称差异、同名或多个合理点位，未强行写入坐标。
- candidates.csv：全部原始候选，可查看多个点位的坐标；use=yes 表示本次选入更新SQL。
- results.json / cache.json：结构化处理结果和真实接口缓存，不含 Key。
- validation.json：独立 MySQL 实际验证结果。

70 个候选中，59 个来自地址解析，11 个来自机构名称搜索。均为 GCJ02；全部标记 review，不视为现场核验或测绘成果。

## 候选筛选依据

- 唯一精细的本市地址匹配。
- 多个地址结果中，原始道路及门牌地址唯一一致。
- 相同完整地址出现门址和门牌号，且点位间距不超过150米时，按精度级别优先门址；不能据此声称绝对准确。
- 机构全名、去掉已知行政前缀后的名称、或清单括号内明确别名一致，并有相同门牌地址或150米内地址点佐证。
- JS PlaceSearch 按 city=南京市、citylimit=true 请求；当SDK未返回adcode时保持空值，不编造行政代码。

没有把道路中心、村庄中心或模糊搜索第一条当成机构位置。31 家未解决记录保留全部候选；例如多家“扬子X村”的原始地址只有“大厂杨村路”，不能把同一个道路中心赋给所有小区。
