# 119警情接入运行说明

## 当前行为

后端启动后10秒进行首轮同步，此后每60秒触发一次。正在执行上一轮时跳过新触发，不排队堆积。每轮从第1页完整查询并核对旧案件状态；当前2265条、20条/页，对应114次分页请求，不是只查第一页。默认最大500页、整轮检查预算240秒、单次完整响应15秒及4MiB，事务语句超时15秒。整轮预算在页/行之间检查，在途请求或事务按自身限时完成后退出；超限记失败，下一轮重新核对。

Token 使用工具同样的RSA算法、117字节分段和当前Unix秒；缓存约9分钟后刷新。GET按用户截图携带token和orderSource请求头，不使用Bearer。HTTP或业务401/403会清理Token并只重试一次；其他失败记日志，不无休止重试。接口凭据按用户要求写入 ruoyi-admin/src/main/resources/application.yml 的 fire.incident119 配置，本说明不重复密码或Token。

## 启动步骤

1. 在现有 dachang 库执行 SQL/fire_119_incident.sql，创建四张空表。已执行且结构一致无需再次导入。此版本没有增加字段或要求额外迁移。
2. 在IDE运行最新 ruoyi-admin 源码，配置 fire.incident119.enabled=true 已启用同步。无需手工启动 secretKey 小工具，也无需手动把Token粘到配置。
3. 观察日志“119警情同步已启用”以及每轮“119同步完成”。缺表、数据库断开、认证或网络失败会记录未完整成功，不清空已有警情。
4. 用若依账号登录，进入大屏“消防警情→119警情”，或 /fire/alarms?source=119。需要 fire:alarms:list 权限以及相应数据范围。

此功能不依赖设备TCP；项目现有 fire.device 配置仍独立控制2000端口，若当前电脑没有10.5.90.50或不调试设备，可按实际环境停用该设备接收开关。本文不自动修改设备配置。

## 数据与范围

全部案件类型、性质、状态均按源记录存储，包括抢险救援、社会救助、虚警和已结案件，不统一变成“待核验火警”。同一(source_system,external_id)只保留一个当前快照，源内容变化时事务更新并追加历史；重复轮询只更新最近获取时间。任一条失败不会产生半条主表/历史，整轮不标记完整成功。

查询参数仍是320116；该范围包含大厂街道外数据。外部记录先正常落库，再按上传 大厂街道.doc 的25个原区域多边形判定。只将inside记录提供给消防警情列表和地图，outside和无法判定的pending记录保留审计。不会按地址关键词过滤，也不把区划编码当作大厂街道。

2026-10-21用户确认文档边界和119源点位均为高德GCJ-02。配置 source-coordinate-system=GCJ02、boundary-coordinate-mode=verified。边界点计入内部，任意原区域命中即纳入；保留原多边形间空隙，不用凸包或外接矩形扩张。命中地区按文档原名保存，包括“白色部分”，详情展示这些原名称。

坐标无效或缺失不借用机构坐标；该记录留在库中待核验。主表各来源时间原文保存在raw_json；明确带+0000偏移的字段按UTC入库，无偏移的lasj保留原墙上时间显示，不把本地发现时间伪装成出动/到场时间。

## 权限与前端

/fire/alarms/list和/fire/alarms/{id}现在统一查询设备事件和大厂街道119警情，由数据库统一排序分页。119前端ID形如119:123，与设备事件ID分开。支持source=119/device、caseType=1/2/3及其他源代码，未传类型时包含全部类型。source=119与kind设备事件过滤不得混用，前端切来源会清理不兼容过滤。

/fire/119/status返回同步状态和当前权限范围内的记录计数，不向前端提供密码、公钥或外部Token。设备原有 /fire/alarms/stats 继续只统计设备事件，主机历史不混入119案件。119详情只读，无模拟处置、视频或人员关联。

数据归属 fire.incident119.dept-id / supervisor-user-id 默认为空，不自动猜测部门。管理员可见；普通角色需配置对应部门/人员归属及若依权限后可见，权限不足不会回退演示数据。归属字段只在新入库时初始化，源同步不覆盖已有人工归属。

## 排查方式

检查 fire_119_sync_state 的 last_result、last_completed_at 和连续失败次数；检查 fire_119_sync_log 的批次、页码、错误类型、获取/新增/变化/未变/失败数。成功分页不重复保存整页原文；不记录认证响应原文或Token。HTTP状态和JSON业务码分开处理，接口HTML、超时、认证失败、缺表等会停止当前轮，保留已提交记录。

源接口按来警时间排序、没有更新时间过滤或分页快照标识，完整扫描期间新数据可能导致页间漂移。下一轮重新从首页核对并按ID去重；本实现不能声称绝对不漏每一次瞬时状态变化。数据/日志持续增长，历史仅有源内容变化才追加；上线后需结合保留周期制定归档策略。

## 已提供的验证入口

- tools/119-secret-key/verify_project.py：临时MySQL和本机模拟HTTP，结束自动关闭；覆盖RSA、请求头、Token缓存刷新、分页、去重、状态变化、边界、权限和回滚，不访问业务库或公网接口。
- RuoYi-Vue3/tests/fire/incident119.test.mjs：案件类型/状态、地图坐标来源和主机历史隔离。
- RuoYi-Vue3/tests/fire/incident119.browser.cjs：实际Vue浏览器页面，使用HTTP测试响应覆盖来源筛选、详情、异常、空态、窄屏等。

本次开发不自动启动实际ruoyi-admin、不强制运行公网同步，不把result.json导入业务数据库。实际部署后首轮同步及真实页面验收仍需运行最新项目完成。
