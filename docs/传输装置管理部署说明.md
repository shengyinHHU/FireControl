# 多台用户信息传输装置管理

本次提供数据库升级及台账导入 SQL，未直接修改正在运行的业务数据库，也未重启真实接收服务。

## 部署顺序

1. 备份 dachang 数据库，保存当前后端配置。停止旧版后端后再升级，避免旧程序读取待配置台账时发生兼容问题。
2. 已安装 `SQL/fire_device_access.sql` 的数据库先执行 `SQL/fire_gateway_management_upgrade.sql`。不要删除原来的四张接入表。首次部署需先安装原接入脚本。
3. 再执行 `SQL/fire_gateway_inventory.sql`，导入项目 Excel 中的36台用传及36条主机台账资料。两份脚本已在隔离 MySQL 中验证重复执行；台账导入不覆盖人工维护。
4. 在 IDE 启动最新 ruoyi-admin，重新构建/部署前端。TCP 仍使用配置文件的 10.5.90.50:2000；最大并发连接数提高为64，可在 fire.device.max-connections 中调整（上限256）。同一地址端口只能有一个接收程序，调试采集程序需先停止。
5. 普通角色按需分配 `fire:hosts:list/add/edit/remove`，设备事件继续使用 `fire:alarms:list`；机构选择还需要已有 `fire:places:list` 及其数据范围。新增数据自动归当前用户/部门，旧装置迁移时保留原机构的管理范围。台账导入记录初始归管理员1，未自动授予普通角色全部权限。

## 当前数据及启用步骤

- 202～237是装置编号，与协议中六字节源地址分开保存。元茂大厦219、220分别登记。用传厂家统一为浙江大华、DH-HY-FAM-1000；Excel 品牌和型号列保存到下挂消防主机。
- 原来 c80000000000 / 10.5.90.49 的大厂街道装置及全部报文、告警保留，不与台账202自动合并。
- 新导入36台装置默认停用，10台带有台账用传IP；其余缺失值留空。安装记录“已连接（已测）”不会变成当前在线。摄像头IP仅为参考，不作为用传地址或摄像头平台编码。
- 页面 `/fire/hosts` 为传输装置管理。装置详情包含基本资料、下挂主机、设备事件、通信报文；全部下挂主机可从主页面查询。主机的系统类型、系统地址未知时均留空；真实报文发现的系统单独记录，核对地址后再维护，不自动合并猜测。
- 已有台账装置：在“待登记报文”核对真实来源IP、装置协议地址、中心协议地址，再回到对应台账装置“编辑”填入，核对单位/编号后启用。协议地址为原始报文中的12位十六进制，不将台账编号直接换算填入。“新增登记”用于台账外新装置，默认也停用；不会自动关联或启用既有台账。
- 未登记报文入口仅管理员可用，最多显示最近100组观测地址。其内容只是观测信息，不能代替设备身份核实。已登记但IP不匹配的拒收记录在该装置的通信报文中查看；若专网经过NAT，允许来源IP应填写服务器实际看到的IP。
- 可手工关联已有监管机构；原始台账单位名称继续保留。未关联时告警仍入库并显示台账单位名，但不虚构地图坐标或重复创建 fire_place。
- 停用/删除或修改装置配置后，提交成功才清除该源地址的在线连接；设备按自身机制重连，其他装置不受影响。在线只代表近期收到并校验过该装置的有效报文，不表示消防主机无故障。
- 删除使用软删除，历史告警及双向原文继续保留。删除的装置不再接收新业务告警；删除的主机地址后续继续上报时仍记事件，但不自动恢复主机管理记录。若要重新使用被删除的相同编号/地址，请管理员先核对历史，不通过另建同地址记录绕过去。
