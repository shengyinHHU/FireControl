# FireControl 若依网站部署攻略：从软件安装到上线验收

编写日期：2026-11-01。适用项目：当前工作区的 `RuoYi-Vue3` 前端与 `RuoYi-Vue-master` 后端。

本文提供由你手动执行的步骤和命令。采用“Windows 本地打包、Linux 服务器运行、宝塔管理 Nginx/MySQL/Redis、systemd 管理 Java 后端”的路线。

服务器型号、操作系统、域名还未确定，因此以下以 **Debian 12、单台服务器、前后端同域名**为示例。Ubuntu 可参考，但软件包和服务管理方式应以实际系统为准；CentOS、Alibaba Cloud Linux、Windows Server 不能原样执行本文的 apt 命令。

所有 `REPLACE_...`、`fire.example.com`、`服务器公网IP` 都是占位符，必须替换。文档没有复制项目中现有的数据库密码、第三方接口密码或密钥。

### 1.2 请求如何流转

```text
用户浏览器
    |
    | HTTPS 443
    v
Nginx
    ├── /、/fire/...、JS/CSS/图片 → 前端 dist 文件
    ├── /prod-api/...            → 127.0.0.1:8080 Java 后端
    └── /_AMapService/...        → 高德地图服务，服务端追加安全密钥

Java 后端
    ├── 127.0.0.1:3306 → MySQL
    ├── 127.0.0.1:6379 → Redis
    ├── 配置启用后 → 119 平台 / 视频平台
    └── 配置启用后 → 独立监听 TCP 2000，接收消防设备数据
```

Nginx 与 Java 是两个独立进程。Nginx 服务正常不代表 Java 正常，网页能显示也不代表业务接口正常。

### 1.3 当前项目的上线边界

这点必须在部署前了解：**部分页面在开发环境能演示，但仍需真实后端接口才能用于生产。部署软件不会补齐这些接口。**

- `npm run dev` 当前默认进入 `firemock` 演示模式。
- `npm run dev:real` 用于对接真实后端的本地开发。
- `npm run build:prod` 构建生产包；`src/api/fire/config.js` 要求同时满足 `import.meta.env.DEV` 才能启用模拟模式，因此生产包不会使用演示免登录和模拟仓库。
- 当前已经存在的真实消防控制器包括场所查询/导入、设备接入、装置与主机管理、警情、查岗、视频及实时通知等。
- 网格、人员、物资、任务、短信、公共二维码等其他演示页面，需要逐项核对真实接口。不要以开发环境的演示成功代替生产验收。
- `src/api/fire/sourcePolicy.js` 对部分真实资源明确限制了通用写操作；例如场所页面的某些增删改能力需要另行开发，权限勾选不能代替接口实现。

首次上线时，先验收实际已实现的功能，只向普通角色开放已经确认可用的菜单。

### 1.4 本项目迁移时必须调整的配置

1. `ruoyi.profile` 当前为 Windows 路径 `D:/ruoyi/uploadPath`，服务器需改为 Linux 持久化目录。
2. `fire.device.bind-address` 当前绑定开发环境内网地址，换服务器后不能直接沿用，否则可能因地址不存在导致后端启动失败。
3. `fire.device`、`fire.incident119`、`fire.video` 当前配置启用了外部接入，首次部署应先明确关闭，再按功能逐项开启。
4. 数据库账号、Redis 密码、Token 签名密钥、119 与视频平台凭据必须按生产环境重新配置。
5. 只上传 `dist` 不会自动建立高德地图代理；必须配置 `/_AMapService`。
6. SSE 警情与 FLV 视频需要关闭代理缓冲，不能仅套用最简单的接口代理配置。
7. 仓库中的部分配置存在凭据明文；对外共享源码或 JAR 前应清理，生产环境使用独立凭据。外置配置能改变运行值，但不会从已有 JAR 中删除打包进去的配置。

## 2. 软件与服务器准备

### 2.1 推荐的软件分工

| 安装位置 | 软件 | 用途 | 是否必须 |
|---|---|---|---|
| 本地 Windows | Node.js 22 LTS 的当前维护补丁版、npm | 前端依赖安装与打包 | 是 |
| 本地 Windows | JDK 17 或已验证的更高版本 | 后端编译 | 是 |
| 本地 Windows | Maven 3.9.x | 多模块后端打包 | 是 |
| 本地 Windows | SSH/SFTP 客户端 | 登录服务器、上传文件 | 是 |
| Linux 服务器 | 宝塔 Linux 面板稳定版 | 图形化管理 | 本文路线使用 |
| Linux 服务器 | Nginx 当前维护的稳定版 | 静态前端、反向代理、HTTPS | 是 |
| Linux 服务器 | MySQL 8.x | 业务数据库 | 是 |
| Linux 服务器 | Redis 7.x 或兼容的已验证版本 | Token、验证码、缓存等 | 是 |
| Linux 服务器 | OpenJDK 17 | 运行后端 | 是 |
| Linux 服务器 | systemd | Java 常驻、开机启动、日志 | 是 |
| Linux 服务器 | PHP、独立 Tomcat、Node.js、Maven | 本文架构不依赖这些服务端组件 | 无需为了本项目安装 |

Node.js、JDK、Maven 从各自官方渠道安装；前端使用仓库锁定的 Vite 6 依赖，不要直接升级到网上教程中的其他大版本。

当前 Spring Boot 文档确认 Java 至少为 17；本文结合项目 POM 选择 Java 17。参考：[Spring Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html)。

### 2.2 服务器资源

作为首次单机部署的规划起点，可考虑 4 核、8GB 内存、100GB SSD，再依据并发、原始报文增长和视频转发流量调整。这里是容量建议，并非经过本项目压测的保证；小规格可以用于测试，正式承载前需观察内存、磁盘和网络。

特别注意：视频转发会消耗服务器公网带宽；原始消防报文和日志会持续增长。磁盘容量、备份空间、带宽不能只按静态网站估算。

购买或确认以下信息：

- Linux 系统版本与架构。
- 公网 IP、SSH 端口、登录用户名/私钥。
- 你能管理的域名，例如 `fire.example.com`。
- 业务需要的内网/VPN/专线连接，尤其是消防设备和受限 119 平台。
- 云服务器快照与数据备份方式。

### 2.3 本地工具安装与检查

如果本地已经可以正常构建，保留现有可用工具链，先执行下方版本检查即可。首次安装可按以下顺序：

1. **Node.js**：从 [Node.js 官网](https://nodejs.org/en/download) 选择 Node.js 22 的当前维护补丁版、Windows x64 安装包。运行安装器，安装 Node.js 与 npm，并加入 PATH。安装后重新打开终端。
2. **JDK**：可以从 [Eclipse Temurin JDK 17 下载页](https://adoptium.net/temurin/releases/?version=17&os=windows&arch=x64&package=jdk) 获取 Windows x64 的 JDK 包。确认下载的是 JDK 17。安装后记录 JDK 主目录，例如 `D:\env\jdk-17`，该目录下应有 `bin\java.exe` 和 `bin\javac.exe`。
3. **Maven**：从 [Apache Maven 官方下载页](https://maven.apache.org/download.cgi) 选择维护中的 Maven 3.9.x **Binary zip archive**，解压到例如 `D:\env\apache-maven-3.9.16`。不要下载 Source 源码包，也不要仅把压缩包放进 PATH。
4. 在 Windows 搜索“编辑系统环境变量”，进入“环境变量”。设置 `JAVA_HOME` 为实际 JDK 主目录、`MAVEN_HOME` 为实际 Maven 主目录；这两个值都不要带末尾的 `bin`。在相同范围的 Path 中添加 `%JAVA_HOME%\bin` 与 `%MAVEN_HOME%\bin`。
5. 关闭旧终端，重新打开 PowerShell，执行下方检查。若检测到旧版本，检查 Path 中旧 Java/Maven 路径是否排在前面，以及 `JAVA_HOME` 是否指向另一套 JDK。

上述路径只是示例，以你的实际解压目录为准。不要使用 `setx PATH ...` 整体重写已有 Path，图形界面逐项添加更容易核对。

**本地 Windows PowerShell 执行：**

```powershell
node --version
npm.cmd --version
java -version
mvn.cmd -version
Get-Command java
Get-Command mvn.cmd
```

重点：`java -version` 和 `mvn.cmd -version` 显示的 Java 可能不同，因为 Maven 优先使用 `JAVA_HOME`。编译时以 `mvn.cmd -version` 的 Java 信息为准。两者都应符合所选版本要求。

PowerShell 如果限制执行 `npm.ps1`，使用本文的 `npm.cmd` 即可，不需要为打包而放宽全局执行策略。

## 3. 登录服务器并安装宝塔

### 3.1 SSH 登录

可以使用 PuTTY、具有适用授权的 Xshell，或者本机已经安装的 OpenSSH。

**本地 PowerShell 执行，用户名按云厂商实际配置替换：**

```powershell
ssh root@服务器公网IP
```

如果 SSH 端口不是 22：

```powershell
ssh -p 你的SSH端口 root@服务器公网IP
```

如果云厂商要求使用 `debian`、`ubuntu` 等普通用户，应先使用对应用户名登录，然后在服务器执行 `sudo -i`。

**服务器终端执行：**

```bash
cat /etc/os-release
uname -m
free -h
df -h
ip -br addr
```

确认是本文的 Debian 路线、资源正常，并记下实际网卡地址。云厂商公网 IP 经常通过 NAT 映射，不一定出现在服务器网卡上。

### 3.2 宝塔安装

新服务器应使用纯净系统；已有网站、数据库或业务的服务器先备份并评估兼容性。

打开 [宝塔官方下载页](https://www.bt.cn/new/download.html)，选择 Linux 面板稳定版和匹配系统，复制当时的官方安装命令。

以当前官网列出的 12.0.0 稳定版命令为例，**服务器 root 终端执行**：

```bash
wget -O install.sh https://download.bt.cn/install/installStable_12.sh && bash install.sh 3Tmtilpm
```

若服务器缺少 wget，Debian 可先执行：

```bash
apt update
apt install -y wget ca-certificates
```

根据安装提示确认安装。保存终端最终显示的面板完整地址、面板账号、面板密码。面板账号与 Linux SSH 账号不同。

在云安全组及服务器防火墙中放行安装结果显示的**实际面板 TCP 端口**，来源优先限制为你的管理公网 IP。浏览器访问完整面板地址，包含端口和安全入口路径。

忘记面板地址可在服务器执行：

```bash
bt 14
```

操作依据：[官方安装说明](https://docs.bt.cn/getting-started/quick-installation-of-bt-panel)、[面板端口说明](https://docs.bt.cn/getting-started/allow-panel-port-access/)。面板端口不要固定假设为 8888。

## 4. 在服务器安装项目依赖

### 4.1 通过宝塔安装 Nginx、MySQL、Redis

**宝塔页面操作：**

1. 首次登录如果弹出 LNMP/LAMP 套件，先关闭自动推荐窗口。
2. 打开“软件商店”，按实际版本可见的“运行环境”分类或搜索框查找。
3. 安装 Nginx 维护中的稳定版本。
4. 安装 MySQL 8.x，完成 root 管理密码设置。
5. 安装 Redis，记录实际版本，设置连接密码。
6. 依次确认这三个服务已启动，并配置开机启动。

本文选择由宝塔统一管理这三项软件，避免再用 `apt install nginx mysql-server redis-server` 安装第二份相同服务。官方界面操作参见：[宝塔基础环境安装](https://docs.bt.cn/getting-started/install-basic-environment)。

在软件管理页面找到配置文件，确认 MySQL 只监听本机或必要的内网地址；Redis 单机示例配置为：

```conf
bind 127.0.0.1
protected-mode yes
requirepass REPLACE_REDIS_PASSWORD
```

`REPLACE_REDIS_PASSWORD` 必须换成强随机密码，并与后端配置一致。修改后使用宝塔重启 Redis。MySQL 和 Redis 无需向全公网开放。[Redis 官方安全说明](https://redis.io/docs/latest/operate/oss_and_stack/management/security/)

### 4.2 安装 Java 17 和辅助工具

**服务器 Debian root 终端执行：**

```bash
apt update
apt install -y openjdk-17-jdk-headless curl unzip zip rsync openssl
java -version
readlink -f /usr/bin/java
```

确认输出为 Java 17。如果同时装了多个 Java：

```bash
update-alternatives --config java
```

选择本项目使用的 Java，然后再次检查。本文 systemd 的启动路径是 `/usr/bin/java`，它实际指向的版本必须正确。

### 4.3 验证软件与监听端口

宝塔安装的软件可执行文件不一定在默认 PATH 中。常见路径如下，**以实际安装结果为准**：

```bash
/www/server/nginx/sbin/nginx -v
/www/server/mysql/bin/mysql --version
/www/server/redis/src/redis-cli --version
ss -lntp
```

Redis 登录验证，密码在提示后输入，避免直接放进命令参数：

```bash
/www/server/redis/src/redis-cli -h 127.0.0.1 -p 6379 --askpass PING
```

预期返回 `PONG`。如果该版本客户端不支持 `--askpass`，在宝塔工具中验证连接，或使用兼容的 Redis 客户端；不要为了通过测试关闭认证。

## 5. 网络与目录规划

### 5.1 安全组和防火墙

云安全组与服务器本机防火墙都要允许对应流量。不要在当前仅有一个 SSH 会话时直接启用未知规则的防火墙，避免锁住自己。

| 端口 | 用途 | 允许来源 |
|---|---|---|
| 实际 SSH 端口，常见 22/TCP | 远程管理、SFTP | 管理员 IP 或 VPN |
| 宝塔实际面板端口/TCP | 面板管理 | 管理员 IP 或 VPN |
| 80/TCP | HTTP、证书验证、跳转 HTTPS | 网站允许的访问范围 |
| 443/TCP | 正式 HTTPS 网站 | 网站允许的访问范围 |
| 8080/TCP | Java HTTP | 本文只绑定 127.0.0.1，不开放公网 |
| 3306/TCP | MySQL | 本机访问，不开放公网 |
| 6379/TCP | Redis | 本机访问，不开放公网 |
| 2000/TCP | 消防装置接入，启用后才需要 | 已核实的设备网络/VPN 出口 |

HTTP 的反向代理配置不处理消防 TCP 2000。服务器能访问互联网，也不代表现场设备能访问服务器；专网地址需要有效路由、VPN 或专线。

### 5.2 创建业务用户与目录

本文让 Java 使用专用 Linux 用户运行，文件归属按用途分别设置。

**服务器 root 终端逐条执行：**

```bash
id firecontrol
```

如果提示该用户不存在，再执行：

```bash
useradd --system --user-group --home-dir /opt/firecontrol --shell /usr/sbin/nologin firecontrol
```

创建目录：

```bash
install -d -m 755 /opt/firecontrol
install -d -m 755 /opt/firecontrol/app
install -d -m 750 -o root -g firecontrol /opt/firecontrol/config
install -d -m 755 /opt/firecontrol/nginx
install -d -m 750 -o firecontrol -g firecontrol /opt/firecontrol/data/upload
install -d -m 750 -o firecontrol -g firecontrol /home/ruoyi/logs
install -d -m 700 /opt/firecontrol/incoming
install -d -m 700 /opt/firecontrol/sql
install -d -m 700 /opt/firecontrol/backups
install -d -m 755 /www/wwwroot/firecontrol
```

| 路径 | 内容 |
|---|---|
| `/opt/firecontrol/app/ruoyi-admin.jar` | 当前运行的后端包 |
| `/opt/firecontrol/config/application-prod.yml` | 外置生产配置 |
| `/opt/firecontrol/config/firecontrol.env` | 数据库等环境变量，root 管理 |
| `/opt/firecontrol/data/upload/` | 用户上传、查岗证据等持久文件 |
| `/home/ruoyi/logs/` | 项目 `logback.xml` 中固定的日志目录 |
| `/opt/firecontrol/incoming/` | 上传安装包的临时区 |
| `/opt/firecontrol/sql/` | 数据库初始化/升级脚本 |
| `/opt/firecontrol/backups/` | 发布前备份 |
| `/opt/firecontrol/nginx/` | 网站公共路由、高德代理配置 |
| `/www/wwwroot/firecontrol/` | 仅存放前端公开文件 |

不要把 JAR、SQL、生产配置、备份、`.env` 或整个源码目录放入网站根目录。

`/home/ruoyi/logs` 来自当前 `logback.xml`，只改 `logging.file.path` 不会自动替换这里的硬编码路径。本文先创建匹配目录，无需改源码。

## 6. 数据库：首次初始化与已有数据库迁移

### 6.1 先选正确路线

| 场景 | 正确处理 |
|---|---|
| 新建空库，想装项目初始结构与资料 | 执行 6.3 的首次初始化 |
| 已有开发库/业务库，要搬到服务器并保留数据 | 导出完整数据库，执行 6.4 的迁移 |
| 服务器上已有运行中的项目，只升级版本 | 备份，停旧应用，执行缺少的增量升级；不要重跑基础初始化 |

**重要：`SQL/ry_20260417.sql` 和 `SQL/quartz.sql` 含 DROP TABLE。只能在确认可初始化的空库使用，不能在现有业务库上重新执行。**

### 6.4 已有数据：迁移完整数据库

如果你希望服务器保留本地已有的场所、坐标、查岗、用户和设备数据，优先使用本节。不要再执行 6.3 的全量初始化。

1. 停止写入或安排维护窗口。
2. 使用原数据库的管理工具导出 `dachang` 的结构与数据。
3. 对 InnoDB 数据可使用 `mysqldump --single-transaction`，期间不要并行改表。
4. 将备份上传到新服务器的私有目录。
5. 在目标服务器创建空 `dachang`，导入备份。
6. 只执行目标库缺少的增量升级脚本，核对后再启动新应用。

**在原数据库所在机器执行，下面为 Linux shell 示例：**


本地 Windows 可以使用相同参数的 `mysqldump.exe`，路径按安装位置替换。使用 `--result-file`，避免 Windows PowerShell 的文本重定向编码影响 SQL。先确认导出命令成功，文件不为空，再上传。

**目标服务器 MySQL 管理会话执行：**

```sql
CREATE DATABASE dachang CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

**目标服务器 Linux 终端执行：**

```bash
/www/server/mysql/bin/mysql --default-character-set=utf8mb4 -u root -p dachang < /opt/firecontrol/backups/dachang-migration.sql
```

已有库重点核对三组升级：

- 查岗：`fire_inspection_contact_upgrade.sql`。
- 装置管理：`fire_gateway_management_upgrade.sql`，完成后才考虑台账导入。
- 119：`fire_119_sync_optimization.sql`、`fire_119_gcj02_scope_upgrade.sql`。

如果此前未建立某业务表，应先建立对应基础表，再升级。备份/迁移还需包含上传文件目录；仅复制数据库不会带走磁盘里的图片证据。

备份参数依据：[MySQL mysqldump 官方文档](https://dev.mysql.com/doc/refman/8.0/en/mysqldump.html)。

### 6.5 建立生产业务数据库账号

先完成上面的管理性导入，再建立只供应用运行的账号。应用账号不需要日常拥有 DROP TABLE、创建用户等管理权限。

**服务器终端进入 MySQL：**

如果用户已存在，先确认用途，再由管理员使用 `ALTER USER` 修改；不要为了绕过报错删除现有业务账号。

建议使用密码管理器生成强随机值；服务器可以逐次执行以下命令生成候选值，然后分别保存：

```bash

```

数据库/Redis 的值必须与第 4、6 节实际设置一致。Token 密钥在首次生成后保持稳定；以后更换会让原登录 Token 失效。

环境变量文件是 systemd 的 `EnvironmentFile` 格式，不是 YAML，也不要写 `export`。简单十六进制密码可避免空格和特殊字符引号问题；有特殊字符时按 systemd 环境文件规则处理，勿把复杂凭据直接拼进命令行。

**服务器 root 终端设置权限：**

```bash

chmod 640 /opt/firecontrol/config/application-prod.yml
chown root:root /opt/firecontrol/config/firecontrol.env
chmod 600 /opt/firecontrol/config/firecontrol.env
```

systemd 管理进程以 root 读取 EnvironmentFile，再将变量交给业务用户。Java 用户无需直接读取该 env 文件。

内容：

```ini
[Unit]
Description=FireControl RuoYi Backend
Wants=network-online.target
After=network-online.target
StartLimitIntervalSec=120
StartLimitBurst=5

[Service]
Type=simple
```

`-Xmx1024m` 是起始示例，要给 MySQL、Redis、Nginx、操作系统和 Java 堆外内存留空间；不要按服务器总内存直接填满。

## 12. Nginx：前端路由、接口代理、SSE 与视频

### 12.1 使用一个公共路由配置文件

在服务器创建：

```text
/opt/firecontrol/nginx/firecontrol-routes.conf
```

写入以下内容。这个文件是 **server 块内部的片段**，不再套 `http {}` 或 `server {}`：

```nginx
client_max_body_size 20m;

# SPA：刷新 /fire/dashboard 等页面时返回首页。
location / {
    try_files $uri $uri/ /index.html;
}

# 新版本首页及时重新验证缓存。
location = /index.html {
    add_header Cache-Control "no-cache" always;
}

# 生产环境不暴露管理调试入口。
location = /prod-api/druid { return 404; }
location ^~ /prod-api/druid/ { return 404; }
location = /prod-api/swagger-ui.html { return 404; }
location = /prod-api/swagger-ui { return 404; }
location ^~ /prod-api/swagger-ui/ { return 404; }
location = /prod-api/v3/api-docs { return 404; }
location ^~ /prod-api/v3/api-docs/ { return 404; }

# 实时警情 SSE：使用 Authorization 请求头，不把 Token 写入 URL。
location = /prod-api/fire/alarms/stream {
    proxy_pass http://127.0.0.1:8080/fire/alarms/stream;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 90s;
    gzip off;
}

# FLV 是持续字节流，不能等完整响应后才交给浏览器。
location ^~ /prod-api/fire/video/flv/ {
    proxy_pass http://127.0.0.1:8080/fire/video/flv/;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 90s;
    gzip off;
}

# 一般接口：末尾的 / 表示去掉 /prod-api/ 前缀。
location ^~ /prod-api/ {
    proxy_pass http://127.0.0.1:8080/;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 10s;
    proxy_read_timeout 60s;
}

# 隐藏文件不应作为网站内容提供；保留证书验证路径。
location ~ /\.(?!well-known/) {
    deny all;
}
```

`client_max_body_size 20m` 与当前后端单次请求上限对齐。后端单文件上限仍为 10MB，查岗证据控制器还有 5MB 限制；Nginx 放宽到 20MB 不会改变这些业务限制。

路径对应必须保持：

```text
浏览器 /prod-api/login        → Java /login
浏览器 /prod-api/captchaImage → Java /captchaImage
浏览器 /prod-api/fire/...     → Java /fire/...
```

不能把一般接口的 `proxy_pass` 随手改成不带末尾 `/` 的地址，否则 `/prod-api` 可能被一起传到后端，导致接口找不到。[Nginx 代理路径规则](https://docs.nginx.com/nginx/admin-guide/web-server/reverse-proxy)

当前 SSE 前端会周期性重连，后端订阅也有有效期。约一分钟结束再连接并不必然是故障；重点检查事件内容是否及时到达、是否出现持续 401/403 或异常高频断开。

### 12.2 在宝塔对应站点引用片段

打开该网站“设置 → 配置文件”。保留宝塔生成的证书验证配置、日志和必要 include，在对应 `server { ... }` 内设置：

```nginx
root /www/wwwroot/firecontrol;
index index.html;
include /opt/firecontrol/nginx/firecontrol-routes.conf;
```

注意：同一个 server 中不能出现两段相同的 `location /`。如果宝塔的“伪静态”文件、默认配置或此前的反向代理已经有同类路由，先备份并整理成一份。不要同时通过 GUI 添加整站代理又粘贴本文整套代理。

前端目录根路径是 `/`。如果你计划把整个网站挂在 `/firecontrol/` 子目录，本文配置不适用，需要同时调整 Vite `base`、路由 history 基路径、接口与资源路径。

### 12.3 检查与重载

**服务器执行，下面路径对应常见宝塔安装：**

```bash
/www/server/nginx/sbin/nginx -t
```

看到 `syntax is ok` 和 `test is successful` 后，再执行：

```bash
/www/server/nginx/sbin/nginx -s reload
```

检查失败时先修复，不要通过反复重启掩盖错误。若安装路径不同，使用宝塔软件管理中的检查/重载功能，确保操作的是正在使用的那一份 Nginx。[Nginx 命令说明](https://nginx.org/en/docs/switches.html)

测试代理：

```bash
curl -i -H 'Host: fire.example.com' http://127.0.0.1/prod-api/captchaImage
```

域名替换成实际站点域名。应返回后端 JSON，而不是前端 HTML 或 Nginx 502 页面。

## 13. 高德地图生产环境

本地 Vite 有 `/_AMapService` 开发代理，但打包后的 dist 不携带代理服务器。生产需要 Nginx 对应配置。

### 13.1 准备 Key 与安全密钥

1. 在高德控制台确认使用 Web 端 JS API Key。
2. 配置生产域名与对应授权限制。
3. 浏览器 Key 放入前端 `.env.production.local`，重新打包。
4. 安全密钥 jscode 仅保存在服务器代理配置。

生产商业使用的服务许可和配额应在高德控制台按你的实际业务确认；不能以开发 Key 可以加载地图推定已满足所有商业使用条件。

### 13.2 配置专用代理文件

新建：

```text
/opt/firecontrol/nginx/firecontrol-amap.conf
```

内容：

```nginx
location ^~ /_AMapService/v4/map/styles {
    set $args "$args&jscode=REPLACE_AMAP_SECURITY_JSCODE";
    proxy_ssl_server_name on;
    proxy_set_header Host webapi.amap.com;
    proxy_pass https://webapi.amap.com/v4/map/styles;
}

location ^~ /_AMapService/ {
    set $args "$args&jscode=REPLACE_AMAP_SECURITY_JSCODE";
    proxy_ssl_server_name on;
    proxy_set_header Host restapi.amap.com;
    proxy_pass https://restapi.amap.com/;
}
```

替换两处占位符，两个值应为对应 Key 的同一个安全密钥。不要把这个文件复制进网站公开目录。

**服务器设置权限：**

```bash
chown root:root /opt/firecontrol/nginx/firecontrol-amap.conf
chmod 600 /opt/firecontrol/nginx/firecontrol-amap.conf
```

常见宝塔 Nginx master 以 root 启动，可以读取该文件。如果你的 Nginx master 使用其他用户，应按实际运行方式授予必要读取权限。

在网站 `server { ... }` 中增加：

```nginx
include /opt/firecontrol/nginx/firecontrol-amap.conf;
```

检查 `nginx -t` 后重载。若不开启高德地图，不要添加这个未填写凭据的片段。

上述结构依据项目 `amap-deployment.md` 与[高德安全密钥官方说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。

### 13.3 验收

打开浏览器开发者工具 Network，确认：

- `https://webapi.amap.com/maps?...` SDK 请求成功。
- `/_AMapService/...` 返回地图资源，不是前端 index.html。
- 安全密钥没有出现在前端 JS 或浏览器发出的 jscode 查询参数中。
- 地名、道路和高德标识正常。
- 业务场所是否上图，取决于真实坐标及审核状态；底图正常并不代表所有场所已经定位。

Nginx 的完整配置输出可能包含服务端密钥。对外分享排查日志前，要对配置文件和 `nginx -T` 输出做脱敏。

## 14. 域名与 HTTPS

### 14.1 DNS

在域名 DNS 控制台添加：

```text
主机记录：fire
记录类型：A
记录值：服务器公网 IPv4
```

示例域名即 `fire.example.com`。如果未部署 IPv6，不要留一个指向错误主机的 AAAA 记录。

**本地 PowerShell 检查：**

```powershell
Resolve-DnsName fire.example.com
```

确认地址指向目标服务器，站点配置中的 `server_name` 也填写了相同域名。域名接入手续按你的服务器所在地及云厂商要求办理。

### 14.2 通过宝塔签发或安装证书

**宝塔页面操作：**

1. 打开网站设置中的 SSL/证书管理。
2. 申请适用的 ACME 证书，或上传已有合法证书与对应私钥。
3. 使用 HTTP 验证时，域名解析和 80 端口必须可达，保留 `/.well-known/acme-challenge/` 验证路径。
4. 签发后开启 SSL，确认 `https://你的域名` 无证书警告。
5. HTTPS 验证通过后，再开启 HTTP 跳转 HTTPS。
6. 确认自动续期任务有效，并安排到期检查。

如果 HTTP 与 HTTPS 分成两个 server，**路由与高德 include 应放在真正处理 HTTPS 业务的 server 中**；仅在 HTTP 块配置代理，开启强制 HTTPS 后接口仍会失败。

不要整段覆盖宝塔生成的 SSL 配置；保留证书路径、续期验证和面板要求的标记。

### 14.3 为什么本项目需要 HTTPS

视频对讲代码明确检查浏览器安全上下文。公网 `http://服务器IP` 不满足正常麦克风使用条件。正式对讲应使用可被浏览器信任的 HTTPS 域名，并由用户授予麦克风权限。

宝塔管理面板的 HTTPS 与业务网站的 HTTPS 是两套配置。给面板配置证书，不等于给消防网站配置了证书。

## 15. 逐项开启消防 TCP、119、视频与对讲

先完成“登录、页面、数据库查询、上传、Nginx、HTTPS”基础链路，再逐项开启外部系统。

### 15.1 消防设备 TCP

1. 确认新服务器到现场装置网络可达；私网设备通常需要 VPN/专线或经过确认的 NAT 方案。
2. 使用 `ip -br addr` 查看服务器实际本机地址，选择设备网络可以到达的那个网卡地址。
3. 确认 2000 端口未被旧版服务或调试采集工具占用。
4. 防火墙/安全组只允许已核实的设备网络或 VPN 出口访问 TCP 2000。
5. 核对 `fire_gateway` 中的装置协议地址、中心地址、允许来源 IP、所属机构与启用状态。

编辑 `/opt/firecontrol/config/firecontrol.env`：

```ini
FIRE_DEVICE_ENABLED=true
FIRE_DEVICE_BIND=REPLACE_ACTUAL_LOCAL_INTERFACE_IP
```

这里的占位值必须改成新服务器实际拥有的网卡 IP；不是设备 IP，也不一定是云公网 IP。只有在明确需要监听所有 IPv4 网卡、并已做好网络限制时才考虑 `0.0.0.0`。

**服务器执行：**

```bash
ss -lntp
systemctl restart firecontrol
journalctl -u firecontrol -n 100 --no-pager
ss -lntp
```

当前设备服务绑定失败会影响应用启动。如果不准备联调，保持 `FIRE_DEVICE_ENABLED=false`，不要为了启动成功随意填写不存在的地址。

台账与现场核验：

- 台账编号不是 12 位十六进制协议地址，不能直接互相换算。
- 允许来源 IP 要填服务器实际看到的对端 IP；NAT 后可能不同于设备配置地址。
- 36 台台账导入记录默认停用；逐台核实后启用。
- 原始报文保留并不等于身份核验或成功接收业务事件，检查解析/拒收原因。
- “在线”表示近期收到有效报文，不代表消防设备无故障。
- 接收服务按协议会发送确认，现场联调应协调设备管理方，避免同时运行两个接收程序。

项目已有的具体台账说明见 `docs/传输装置管理部署说明.md`。

### 15.2 119 同步

先确认：

- 119 四张表及两份升级脚本已安装。
- 新服务器具备访问项目配置平台地址及目标端口的网络条件。
- 如对方限制访问来源，已把新服务器出口 IP 纳入允许范围。
- 拥有生产账号、密码、平台公钥等实际凭据。
- `dachang-only`、坐标系、区域边界和数据归属符合本项目要求。

环境文件新增/修改：

```ini
FIRE_119_ENABLED=true
FIRE_119_ACCOUNT=REPLACE_ACCOUNT
FIRE_119_PASSWORD=REPLACE_PASSWORD
FIRE_119_PUBLIC_KEY=REPLACE_PUBLIC_KEY_BASE64
```

模板保留了包内的接口地址和同步策略；若生产平台地址、来源标识或区域发生变化，应在外置 YAML 的 `fire.incident119` 下显式覆盖。

`dept-id`、`supervisor-user-id` 应填写真实部门/用户 ID，并在权限验收中检查。留空时普通角色可能看不到对应数据，不能通过关闭数据权限解决。

修改后重启服务，通过日志、页面同步状态、`fire_119_sync_state`/`fire_119_sync_log` 核对。当前同步器在应用启动后按配置自行运行，不需要为了启动同步再额外建立一个重复的 Linux cron 任务。

### 15.3 视频平台与对讲

环境文件新增/修改：

```ini
FIRE_VIDEO_ENABLED=true
FIRE_VIDEO_APP_ID=REPLACE_APP_ID
FIRE_VIDEO_APP_SECRET=REPLACE_APP_SECRET
FIRE_VIDEO_ENTERPRISE_USER=REPLACE_ENTERPRISE_USER
```

配置 `fire.video.allowed-user-ids` 时，填写实际允许使用视频的用户 ID，例如：

```yaml
fire:
  video:
    allowed-user-ids: [100, 101]
```

这是对完整生产 YAML 中现有字段的修改，不要另加第二个重复的 `fire:` 顶层键。

普通用户除角色中的 `fire:video:*` 权限外，还要满足视频显式授权要求；管理员的正常访问不代表普通角色已经通过授权。

网络链路分别验证：

- Java 到 `vcp.21cn.com` 等项目当前代码指定的平台 API。
- Java 到 `.ctyunxs.cn` 媒体地址及当前 RTC 信令网关。
- 用户浏览器到平台返回的 WSS 对讲网关。
- WebRTC 使用时，浏览器到实际媒体网络；仅开放网站服务器 443 不保证 ICE/媒体链路可用。

当前对讲 WSS 由浏览器直接连接平台返回地址；它不是项目 SSE，也不是简单添加一个 Nginx `Upgrade` 头就能解决所有问题。

当前代码采用 Java HTTP 媒体中转/平台 SDK，未发现把本机 FFmpeg 作为必备执行程序的部署要求。不要在未确认用途前额外安装媒体服务器或开放整段未知端口。

先测试视频资源列表，再测试实际摄像头播放，再在获得现场许可后测试麦克风/对讲。保存 `vendor/official-talk`、`vendor/official-rtc` 静态资源。真实对讲会发送音频，应按现场使用要求操作。

## 16. 账号、角色和数据权限

### 16.1 首次登录

访问 `https://你的域名/login`，使用你确认的管理员账号与密码。

- 如果迁移已有库，使用迁移前的实际账号密码。
- 如果从初始化 SQL 建库，先确认 `sys_user` 初始账号以及该项目实际使用的初始密码。
- SQL 里保存的是密码哈希，不能把该字符串直接当登录密码。
- 本项目根目录 SQL 与后端目录 SQL 内容不同，不保证网上“若依默认密码”适用于这份数据。

管理员登录后立即修改初始密码，核对手机号、用户状态、账号与部门归属。

### 16.2 普通角色验收

在“系统管理 → 角色管理”中配置：

- 消防页面的对应菜单/功能权限。
- 场所 `fire:places:list`。
- 主机/装置管理 `fire:hosts:list/add/edit/remove`。
- 警情 `fire:alarms:list`，实际可写动作还需对应后端已实现。
- 查岗 `fire:inspections:list/add/edit`，按具体操作分配。
- 视频 `fire:video:list/preview/talk` 等，按项目脚本实际登记项分配。
- 数据范围：本部门、部门及以下、本人或经过确认的自定义部门。

脚本登记权限节点，不等于自动授权普通角色。前端消防路由部分为静态受控路由，不要再手动添加一套相同 `/fire/...` 路径造成重复菜单。

场所、装置、119 警情的数据归属也要设置。管理员能看见、普通用户列表为空时，优先检查权限与归属；不要直接改成所有人全量可见。

每种实际角色至少准备一个测试账号，逐项测试“可见、可操作、应被拒绝”的边界。新建用户后重新登录，避免拿旧权限缓存验收。

在已安排的维护时间，通过云控制台重启服务器，再检查：

- Nginx、MySQL、Redis 与 Java 都能恢复。
- Java 启动早于数据库就绪导致失败时，服务能按预期恢复；如达到失败限制，排查后手动 reset-failed/start。
- 上传文件、配置和数据库仍存在。
- 设备连接重建、119 同步正常。
- 普通用户仍符合权限边界。

这是首次上线必做的持久化与开机启动验证。

## 18. 后续更新、备份与回滚

### 18.1 更新前备份

先上传新包到 `incoming`，此时不要覆盖运行目录。安排维护窗口、停止写入；涉及设备接入时协调现场重连。

**服务器执行：**

```bash
systemctl stop firecontrol
release_stamp=$(date +%Y%m%d-%H%M%S)
install -d -m 700 "/opt/firecontrol/backups/$release_stamp"
cp -a /opt/firecontrol/app/ruoyi-admin.jar "/opt/firecontrol/backups/$release_stamp/"
cp -a /opt/firecontrol/config "/opt/firecontrol/backups/$release_stamp/"
tar -czf "/opt/firecontrol/backups/$release_stamp/frontend.tar.gz" -C /www/wwwroot/firecontrol .
tar -czf "/opt/firecontrol/backups/$release_stamp/uploads.tar.gz" -C /opt/firecontrol/data upload
```

如果配置已调整为其他持久目录，相应替换路径。上传数据很大时使用受控备份/快照方案，预留足够维护时间和空间。

备份数据库，管理密码交互输入：

```bash
/www/server/mysql/bin/mysqldump -u root -p --single-transaction --no-tablespaces --routines --triggers --events --set-gtid-purged=OFF --default-character-set=utf8mb4 --result-file="/opt/firecontrol/backups/$release_stamp/dachang.sql" dachang
```

确认每条命令成功后再继续；不要把失败后生成的空 SQL 当成备份。包含凭据和业务数据的备份要限制权限，并复制到经过授权的异机存储，不能只保留同一块系统盘。

### 18.2 更新后端与前端

1. 数据库有变动时，使用管理员账号先执行本次需要的增量脚本；不要重跑带 DROP 的基础脚本。
2. 安装新 JAR。
3. 解压新的前端文件到网站目录。
4. 恢复公开文件读取权限。
5. 检查/重载 Nginx，启动 Java。
6. 完成关键功能验收，再结束维护。

**服务器执行：**

```bash
install -m 644 -o root -g root /opt/firecontrol/incoming/ruoyi-admin.jar /opt/firecontrol/app/ruoyi-admin.jar
unzip -o /opt/firecontrol/incoming/frontend-dist.zip -d /www/wwwroot/firecontrol
chown -R root:root /www/wwwroot/firecontrol
find /www/wwwroot/firecontrol -type d -exec chmod 755 {} \;
find /www/wwwroot/firecontrol -type f -exec chmod 644 {} \;
/www/server/nginx/sbin/nginx -t
```

Nginx 检查通过后：

```bash
/www/server/nginx/sbin/nginx -s reload
systemctl start firecontrol
systemctl status firecontrol --no-pager -l
journalctl -u firecontrol -n 100 --no-pager
```

本路线在短维护窗口覆盖前端，保留旧的哈希静态文件，以便已经打开的旧页面暂时继续加载。覆盖解压不会清理废弃公开文件；需要清理时先对照备份和当前产物清单，确认不会误删正在使用的资源。不要使用未经检查的 `rm -rf` 或整盘同步删除。

若需要无中断发布，可再改为版本目录和原子切换，并保留旧静态资源访问策略；本文先使用容易核对的维护窗口发布。

### 18.3 回滚

出现问题先停止新应用、保存报错日志，然后判断数据库是否已升级：

- **仅代码变化，数据库兼容**：恢复上一版 JAR、配置及前端，重启后验收。
- **数据库已发生不向后兼容的变更**：旧 JAR 可能无法读取新库，需要协调数据库恢复和上传目录的一致性，不能只回滚 JAR。
- **上线后已有新业务数据**：恢复旧备份会丢失备份之后的数据，必须先评估保留方式和维护影响。

JAR 恢复示例，日期目录替换为已核实的备份路径：

```bash
systemctl stop firecontrol
install -m 644 -o root -g root /opt/firecontrol/backups/REPLACE_BACKUP_TIMESTAMP/ruoyi-admin.jar /opt/firecontrol/app/ruoyi-admin.jar
```

前端需要精确恢复时，先把当前前端目录整体保留到新的备份位置，再建空的前端目录，解压旧 `frontend.tar.gz`；操作前核实源/目标绝对路径，避免把上传目录或其他站点目录一起移动。

数据库备份恢复命令示例只用于已确认允许覆盖的恢复目标：

```bash
/www/server/mysql/bin/mysql --default-character-set=utf8mb4 -u root -p dachang < /opt/firecontrol/backups/REPLACE_BACKUP_TIMESTAMP/dachang.sql
```

不要在正常服务中为“试一下备份”覆盖生产库。恢复演练应先在隔离环境进行。

### 18.4 日常维护

- 定期检查异机备份是否可恢复。
- 关注 `/home/ruoyi/logs`、`fire_protocol_message`、119 同步日志和视频带宽。
- 保持已验证软件版本的维护补丁，升级大版本前先在测试环境验证。
- 检查证书自动续期、域名与平台账号有效期。
- 不随意清空 Redis；这会影响登录状态、验证码和缓存。
- 消防原文与业务记录的保留/归档周期由业务要求确认后再制定，不直接批量删历史表。

## 19. 常见故障排查

| 现象 | 优先检查 |
|---|---|
| 宝塔面板打不开 | 实际面板端口、安全组、本机防火墙、安全入口路径、管理来源 IP |
| 网站显示 Nginx 欢迎页 | 请求是否命中正确 `server_name`，DNS 是否指向目标服务器 |
| 403 Forbidden | root 目录是否正确，是否有 index.html，父目录及文件读取权限 |
| 刷新业务页面 404 | `try_files ... /index.html` 是否在实际生效的 HTTPS server 中 |
| JS 返回 HTML / MIME 错误 | 静态文件是否缺失、压缩包是否多套 dist 目录、是否上传了不配套的新旧文件 |
| `/prod-api` 返回 HTML | API location 没生效，落入前端 SPA 回退；检查重复路由与配置所在 server |
| Nginx 502 | Java 没启动、8080 未监听、代理端口错误；先 curl 本机后端 |
| 登录/验证码 500 | Redis 连接/密码、数据库连接、后端首个异常 |
| 数据库 Access denied | 用户密码、账号来源主机、JDBC 地址、生产外置配置是否加载 |
| Unknown column | 旧表缺少增量升级；`IF NOT EXISTS` 不升级旧表 |
| Table doesn't exist | 数据库导错库、某业务脚本漏执行、脚本中 USE 改变了目标库 |
| Cannot assign requested address | 消防 TCP 仍绑定不属于新服务器的内网 IP |
| Address already in use | 已运行第二个 JAR、旧接收程序或调试工具占用端口 |
| UnsupportedClassVersionError | 运行 Java 太旧，或构建/运行版本不匹配 |
| Unable to access jarfile | 上传路径不对、文件名错误、Linux 文件权限不足 |
| 日志/上传 Permission denied | 业务用户是否拥有上传目录与 `/home/ruoyi/logs` 写权限 |
| 管理员有数据，普通用户没有 | 功能权限、部门数据范围、场所/装置/119 的真实归属 |
| 某菜单接口 404 | 先确认该模块真实后端是否已实现，不能只归因于 Nginx |
| 地图空白或报 Key 错误 | JS Key、域名限制、前端构建值、`/_AMapService`、服务端 jscode、网络 |
| 地图正常，场所没点位 | 场所坐标、审核状态和权限，不等同于底图故障 |
| SSE 更新延迟 | `proxy_buffering off`、禁用缓存/压缩、其他前置网关是否还在缓冲 |
| SSE 每分钟重连 | 当前代码有订阅有效期与前端重连机制，结合事件与状态判断 |
| FLV 一直等待/延迟很大 | 流式代理缓冲、后端媒体连通、平台与摄像头在线状态 |
| 对讲拿不到麦克风 | HTTPS 是否可信、浏览器权限、音频设备与安全上下文 |
| 对讲/RTC 连接失败 | 浏览器到 WSS/媒体网关的网络、证书、平台权限；不只看 Java 服务器 |
| 上传 413 | Nginx 请求大小限制；与后端 multipart 和具体接口限制一起核对 |
| 重启后无法启动 | 服务开机状态、数据库就绪顺序、外置配置路径、服务失败频率限制 |

排查顺序建议：**本机数据库/Redis → Java 本机接口 → Nginx 本机代理 → DNS/安全组/HTTPS → 浏览器业务功能 → 外部平台。**

常用诊断命令，均在服务器执行：

```bash
systemctl status firecontrol --no-pager -l
journalctl -u firecontrol -n 200 --no-pager
tail -n 100 /home/ruoyi/logs/sys-error.log
/www/server/nginx/sbin/nginx -t
ss -lntp
df -h
free -h
```

Nginx 网站访问/错误日志位置以宝塔该站点配置中的 `access_log`、`error_log` 为准。
