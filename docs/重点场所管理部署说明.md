# 重点场所增删改查

2026-11-14 起，`/fire/places` 使用真实数据库的 PlaceManager / PlaceEditor，支持新增、详情、编辑和删除。页面沿用 Element Plus 和消防主题，导入仍使用原有预检及仅新增流程。

## 数据库与部署

1. 先备份数据库，已安装 `SQL/fire_place_init.sql` 的环境执行 `SQL/fire_place_crud_upgrade.sql`。它只新增 `fire_place.revision`、场所维护共用去重锁和缺失的功能权限，不覆盖场所、联系人或历史资料，可重复执行。
2. 重新编译后端、构建前端。当前本机数据库已用 `python tools/place-management/migrate.py --apply` 完成备份及升级，并核对原有业务资料和角色授权未变。该工具默认只读预检，仅支持已配置的本机 dachang 库；私有备份保存在 `outputs/place-management/backups/`，不纳入 Git。
3. 管理员可以直接使用。普通角色需 `fire:places:list`，按工作职责分别分配 `fire:places:add/edit/remove` 及相应部门/本人数据范围。导入仍单独使用 `fire:places:import`。升级不会自动扩大任何角色授权；权限变更后重新登录刷新会话。
4. 使用现有后端实例，确认其加载最新代码即可，不要同时启动两个占用 8080 / 2000 的实例。

## 行为

- 可维护名称、类别、地址、行业、物业/管理单位、风险等级、主要风险源、备注、多位联系人和经纬度。网格归属、原始 Excel 审计、其他未在表单展示的统计字段保持原值；新记录归当前用户和部门。
- 联系电话允许手机、固定电话和分机，按原文保存。修改已有联系人保留编号；移除联系人采用软删除，不改写历史短信快照或原始导入记录。联系人类型来自已有资料，新联系人可以选择负责人/联系人。
- 经纬度须成对填写或同时留空，使用高德 GCJ-02 坐标。无坐标场所仍可维护；修改地址/坐标后重置为待核验，只有备注等非定位信息变化时保留原核验状态。
- 编辑先读取当前版本及完整联系人；读取失败不能保存。版本冲突明确提示重新打开编辑，失败保留草稿，忙碌时不能重复保存或关闭，放弃未保存修改需要确认。
- 删除是软删除：列表、地图和当前联系人查询隐藏该场所，装置关联、原始来源和历史事件保留。删除后自动回到有效页码，避免末页空白。没有批量硬删除入口。
- 人工新增与导入共用数据库锁；人工新增或改名拦截规范化后的同名场所，保留现有重复记录的正常维护。导入仍沿用其近似名称跳过规则。

## 接口

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/fire/places/list`、`/map`、`/{placeId}`、`/{placeId}/contacts` | list |
| GET | `/fire/places/{placeId}/edit` | list + edit，编辑角色的数据范围 |
| POST | `/fire/places` | list + add |
| PUT | `/fire/places/{placeId}` | list + edit，编辑角色的数据范围及 revision |
| DELETE | `/fire/places/{placeId}?revision=...` | list + remove，删除角色的数据范围及 revision |

写入由 FirePlaceWriteService 明确列出允许维护的字段。客户端提供的归属、创建者、定位核验状态和联系人归属不会被直接信任；实际角色数据范围由 DataScopeAspect 注入。
