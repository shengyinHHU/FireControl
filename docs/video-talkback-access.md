# 语音对讲接入

## 已实现

大屏和管理页共用视频弹窗，在实时画面播放后提供“开始对讲”，启动期间可“取消对讲”，发送语音后可“结束对讲”。开始时自动开启已有直播音轨，用于收听设备声音；若直播没有音轨，会明确提示仅能喊话。结束对讲不停止视频。

后端 `POST /fire/video/devices/{code}/talkback` 复用 fire.video 的 appId、appSecret、enterpriseUser 和 accessToken 缓存，按现有 v1.0 签名与 XXTea 参数调用 `/open/token/vpaas/voice/talkback`，业务参数 deviceCode、domain=1、netType=0。返回仅包含短期 wss/token/sessionId，并设置 Cache-Control:no-store。凭证不进入 URL 参数之外的日志、数据库或本地存储；不要复制签名地址给他人。

前端先申请麦克风和加载 SDK，随后才申请 20 秒语音票据并立即连接 WSS。原始官方 SDK：`docs/talkapi/语音对讲demo-20240704/src/utils/broadcastSdk.js`；适配副本：`RuoYi-Vue3/public/vendor/official-talk/broadcastSdk.js`，原始文件没有修改。保留官方 Recorder、重采样及 A-law 编码，开始发送 `{method:"10000",sessionId,token,level:"1"}`，停止发送 `{method:"10006",sessionId}`；音频采用 8000 Hz、每帧 320 字节 G.711 A-law（约 40 ms）。修复原示例的关闭后发送、一次只取一帧的积压问题；禁用 Recorder 流量统计和录音内容保留。

一页最多一个本地对讲会话。明确结束、取消、关闭弹窗、切换设备、视频重新连接、页面离开、组件卸载都会停止麦克风、关闭 AudioContext 并发送停止报文后关闭套接字。请求返回前取消时，本地麦克风立即释放；迟到的有效票据会仅进行鉴权和停止，不录音。连接 12 秒超时，无音频 8 秒超时或待发送音频超过 8000 字节时，停止并提示手动重试。不会后台自动重新打开麦克风。

## 使用与权限

1. 重启最新 ruoyi-admin 和前端，或重新部署构建产物。沿用现有视频账号配置，无需新建业务表。
2. 管理员可直接测试。其他角色执行 `SQL/fire_video_permissions.sql`（幂等），在若依角色管理授予“视频监控·对讲”（fire:video:talk），同时具有视频查看、播放权限并处于 fire.video.allowed-user-ids 账号授权范围；重新登录生效。只有播放权限不会自动得到喊话权限。本次没有直接修改数据库。
3. 使用受信任 HTTPS 页面或 localhost，允许麦克风访问。普通 `http://10.5.90.50` 不满足浏览器安全上下文要求；生产需配置 HTTPS（证书受客户端信任）。
4. 视频加载后点“开始对讲”，允许麦克风，待显示“正在发送语音”后说话；点“结束对讲”释放麦克风。建议佩戴耳机。

## 设备、网络与协议限制

- 用户提供的官方接口说明明确：仅支持企标 2.0/3.0/4.0，推荐企标 4.0；暂不支持国标平台级联。能播放视频不代表支持对讲；也不能只根据 320116… 编码判断接入类型。铭望府设备是否为支持的企标接入，需要平台或设备厂家确认。
- 摄像头需具备可用拾音器和扬声器，账号需具备该设备对讲权限；设备在线、网络正常且未被其他客户端占用。平台拒绝会显示其错误信息，程序不伪造可用状态。
- 后端需要访问厂家 HTTPS API；浏览器需要直连返回的域名 WSS 及其端口，证书链须有效，防火墙/代理须放行。domain=1 请求仍返回 IP 时拒绝使用；不要关闭浏览器证书验证。
- 收听沿用 FLV 直播，不是独立实时语音下行，音画缓冲会带来延迟；浏览器回声消除不能保证消除经直播绕回来的回声，建议耳机。无直播音轨时不能完成双向收听。
- 真实网关返回 JSON 控制消息，已验证 10001/code=0 表示开始成功，10008/data.talkStatus 中目标设备 status=0/errorMsg=success 表示网关报告该设备通道成功，10007/code=0 表示停止成功。前端现在等待明确的 10001 成功后才启动录音；非零结果立即停止。通道成功仍不能证明设备扬声器实际出声，不把音频写入套接字当作现场播放确认。
- 网络硬断或浏览器崩溃时，停止报文不保证送达；本地录音由浏览器关闭，设备侧会话最终回收依赖厂家网关。没有臆造独立 HTTP 停止接口、心跳协议或跨用户抢占逻辑。

## 验证边界

后端离线编译与前端构建通过。`tools/video/VideoTalkbackCheck.java` 用隔离 HTTP 验证实际签名参数、官方路径、domain=1、netType=0、账号/设备校验和返回值校验。`RuoYi-Vue3/tests/fire/video-talkback.browser.cjs` 使用 Chrome 合成麦克风、模拟 WSS 验证官方录音编码、开始停止报文、320 字节非零音频、拒绝授权、取消迟到票据、关闭弹窗、网络积压和独立权限。报告在前端 docs/verification/video-talkback.json。

最初的自动化测试不向现场发声；随后按用户一次明确授权完成上述限时实测，仍需要现场收听确认。官方说明入口： https://vcp.dlife.cn/portal/document-detail?group=1698897728322854914 ，本次通过本地官方 demo 确认报文，在线文档工具无法读取该入口。

## 凤滨嘉园 II 期实测（2026-10-27）

用户明确授权后，对 32011601031322001321 只发送一次约 3 秒低音量合成测试音，G.711 A-law/8000Hz/单声道，75 包×320 字节=24000 字节，不使用本机麦克风。取票、WSS、设备通道、开始与停止均返回成功；现场暂时无人确认，不能据此宣称扬声器有声音。原始控制响应及统计见 docs/verification/video-talkback-live-audio.json，未保存麦克风录音或语音凭证。没有重复发送测试音。

新增折叠“对讲诊断”：输入音量及峰值（Recorder 的 0–100 级别）、本端成功写入套接字的包数/字节数、网关连接、开始确认及设备通道状态。不要把这些值等同于设备逐包收音回执。说话时峰值始终为 0，优先检查 Windows 的录音输入、静音/增益及浏览器麦克风选择；峰值有变化、包数增长、开始已确认、设备通道成功而现场仍无声，再检查设备扬声器、音量及平台的设备侧音频转发。
