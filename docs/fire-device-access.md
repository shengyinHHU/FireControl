# 消防设备接入部署与验收

已按用户提供的 GB/T 26875.3—2011 Markdown 及其中状态图实现上行接收。首期提供真实装置、主机、事件和通信报文只读查询；未接入远程控制或报警处置流程。

## 导入与启动

1. 在已有 dachang 数据库中审查并执行 SQL/fire_device_access.sql。该脚本创建四张接入表，幂等登记“大厂街道”机关单位和 DH-HY-FAM-1000 装置，不创建虚构下级主机、不填坐标，不重复导入原101家企业。
2. 普通账号授予 fire:hosts:list、fire:alarms:list，并按需要授予 fire:places:list。部门/本人数据范围沿用关联 fire_place 的 dept_id、supervisor_user_id；这些字段未分配时，普通账号可能看不到导入数据。超级管理员可查询全部。
3. 停止 Python 采集工具，确保 TCP 2000 未被占用。
4. application.yml 已默认启用设备接收，绑定10.5.90.50:2000。在 IDE 中直接运行 ruoyi-admin 最新源码即可，不需要填写 Program arguments。以下启动参数仅用于临时覆盖配置：

```text
--fire.device.enabled=true --fire.device.bind-address=10.5.90.50 --fire.device.port=2000
```

或在启动后端的同一 PowerShell 环境设置：

```powershell
$env:FIRE_DEVICE_ENABLED = "true"
$env:FIRE_DEVICE_BINDADDRESS = "10.5.90.50"
$env:FIRE_DEVICE_PORT = "2000"
```

当前配置已使用明确值，以上环境变量如需覆盖，可通过 Spring Boot 标准变量 FIRE_DEVICE_ENABLED、FIRE_DEVICE_BINDADDRESS、FIRE_DEVICE_PORT 设置。环境变量只影响从该环境启动的进程，已打开的 IDE 不会自动继承。更推荐直接修改 application.yml 或使用上述启动参数。不要把后端 HTTP 端口改为2000。

当前 fire.device.enabled=true，点击运行后端会自动开启设备接收。请先导入SQL；需要关闭接收时，将 application.yml 中 enabled 改为 false。程序未替用户修改网卡、防火墙或业务数据库。JDK 17 有界 Socket 工作线程随 Spring 生命周期启停，不额外引入网络库依赖。最多32个并发连接。

5. 前端在 RuoYi-Vue3 运行 npm run dev，若依登录后打开“消防主机”；分为传输装置、消防主机、设备事件、通信报文。大屏“消控主机”统计与事件使用真实数据，其余尚未接入的业务仍明确为演示。
6. 设备 TCP 客户端向10.5.90.50:2000上报，登记来源IP10.5.90.49，协议源地址c80000000000、中心地址640000000000。任何IP或协议地址变化应由管理员核实后更新 fire_gateway，不自动信任未登记设备。

## 数据和协议

- fire_gateway：传输装置，关联 fire_place；装置通信和上报状态分开。
- fire_host：由实际系统/部件等上行报文识别的系统；不凭装置在线虚构主机正常。
- fire_protocol_message：实际TCP接收分段 RAW_CHUNK、完整帧、校验/解析错误和确认记录均保留；session_id关联。首帧确认身份后补充原始分段的gateway_id。未识别来源原文保留在库中，不向普通用户暴露。
- fire_event：按装置协议地址、对象类型和原始对象（含事件时间）SHA256去重，保留首次接收关联。每次重传仍有通信记录且再次确认。该规则对同一对象同秒完全相同事件按一条处理；若厂家存在同秒重复独立事件，需结合厂家事件编号扩展。
- 支持上行类型1、2、3、4、5、6、7、8、21、24、25、26、28，包含多信息对象、GB18030说明、状态位、操作位、版本、配置、原始模拟量和时间。厂商扩展保存为UNSUPPORTED，不猜测为火警。
- 校验启动符、长度、校验和、结束符、版本、登记IP及协议地址。已登记02有效帧及业务对象持久化事务提交后回复03；已登记且可辨识的错误包回复06。未支持类型原文提交后确认，未知命令不执行，不制造确认循环。
- 数据库失败不发送成功确认，接收分段独立持久化，业务事务失败时完整帧/事件/TX排队回滚。日志记录故障，等待设备重传。
- TX的QUEUED表示已提交待发意图，SENT表示整条确认交给本机TCP栈，FAILED表示发送异常，无法断言对端接收情况。若发送后更新状态失败，仍可能停留QUEUED；应结合设备状态和抓包核验，不能把待发当成成功。
- 不主动发送复位、消音、校时、查岗等下行控制。未实现UDP，因为本设备已按TCP验证成功。

## 状态与时间

装置/主机“在线”表示当前服务内至少一个已登记连接近期收到有效帧。空闲断开和在线有效期默认600秒，是可配置联调值，不是协议心跳规定；观察实际周期后调整 fire.device.idle-seconds、online-seconds。后端重启后不会仅凭历史最后通信时间显示在线。

状态位按标准逐位解释：装置14/34是故障状态，不能当作火警；位1置位才是火警。复位操作、故障解除记录不等于人工已办结。页面为设备事件，不提供虚假的接单/办结、视频绑定或其他演示关联。

设备时间、服务器接收时间均保留，超过一天偏差或缺失会提示核验。报文原时间不被改写。大屏近24小时按服务器接收时间判断。装置/系统快照只接受不早于已有设备事件时间的数据，历史补传不能覆盖更新快照；若设备校时回拨，需核验旧快照/时钟后再更新，防止误覆盖。时钟不可信时不能承诺“当前现场状态”。

设备报警上报是待核验的历史事件，不自动证明火灾仍持续；地图没有有效真实坐标时不画虚构点位。“大厂街道”不属于四类企业地图图层，坐标保持空。

## API与权限

- GET /fire/gateways/list、/fire/hosts/list、/fire/hosts/{id}、/fire/hosts/stats：fire:hosts:list。
- GET /fire/protocol/messages：fire:hosts:list，分页查询双向报文（接口单页上限1000条）。
- GET /fire/alarms/list、/fire/alarms/{id}、/fire/alarms/stats：fire:alarms:list，分页查询设备事件。
- keyword、kind、gatewayId等均参数化查询，数据范围由若依服务端注入。
- 数据库接管资源后，空结果、无权限、接口失败均不回退模拟数据。主机、报警及装置写操作暂不开放。

页面每5秒刷新；分页/已提交筛选保存在URL，旧请求不能覆盖新请求，失败清空旧结果并提供重试。大屏仅展示最近1000条事件并提示截断，完整记录使用分页页面。后续其他来源报警需实现真实后端接口后加入，不能继续混入模拟报警。

## 验证与实机验收

- Maven离线源码编译；前端构建及 tests/fire。
- tools/device-capture/verify_project.py：创建临时MySQL并自动停止，重复执行增量SQL、回放8帧真实报文、去重、旧状态保护、强制数据库错误回滚、数据范围SQL、随机本机端口Java接收确认。
- tests/fire/device-access.browser.cjs：真实Vue+Edge浏览器，使用明确固定的HTTP响应，验证成功、空数据、故障重试、只读详情、时间提示、原文、键盘与窄屏；不等于业务数据库联调。
- 实际现场：触发一次火警/故障，核对装置显示、原始报文、数据库事件、大屏与详情，验证断线重连及后端重启；数据库故障时不得显示成功确认。
- 现有实机样本含装置状态21和复位24，未捕获火警置位或下级主机报文。火警/系统/部件其他类型的实机验收仍待补充；不可将合成测试宣称实机通过。
- 完整JAR打包此前存在未缓存插件依赖，本次源码编译不等于新JAR已可部署；优先IDE启动，或在依赖可用环境正常执行Maven package。

## 数据保留

原始报文可能包含设备与场所信息，接口受权限及部门范围限制，不提交采集目录到公开Git。当前不自动删除通信和事件历史，避免擅自决定保留期限；上线前由管理员确定保留天数、容量及归档策略，再配置清理任务。高频设备需要监测表容量与索引，不能无限制长期采集。

## 大屏低延迟警情刷新（2026-10-23）

- 大屏独立每3秒查询警情，事件/火警/故障计数也独立刷新；场所、查岗、摄像头、主机基础统计等仍每30秒刷新。慢资源或119状态查询失败不会阻塞警情列表。
- MapPanel 在大屏接收 alarmRows，只渲染父页面同一份警情，不再重复请求警情。其他独立地图保留原查询能力。图层、聚合和坐标规则不变。
- GET /fire/alarms/stream 需若依 Authorization Bearer 登录和 fire:alarms:list；订阅范围按关联场所的部门/本人权限获取可见网关。只发送 ready/alarm-change，不携带警情详情或设备ID，前端收到后通过原列表接口重新鉴权查询。
- FireIngestService 在事务内注册 afterCommit 回调，回调只标记变化；独立 fire-alarm-push 线程每250ms合并后发通知，不在TCP接收或数据库事务内执行网络发送。后续TX记录写入失败、事务回滚时不会推送。
- 前端使用 fetch SSE，在请求头携带JWT，不把JWT放进URL。每个订阅最多60秒，重连时重新检查登录和数据范围；15秒心跳。断开后5至30秒退避重连，3秒轮询始终保留。401/403停止推送重连，轮询通过现有登录处理反馈。
- 单用户最多5个订阅，全局200个。推送为单JVM尽力通知；多实例间不会广播，轮询负责兜底。突发通知和在途查询合并，不重叠查询；离开大屏关闭连接、计时器，忽略迟到响应。
- SSE响应设置 X-Accel-Buffering: no 和 Cache-Control: no-store。若部署代理忽略该响应头，需为 /prod-api/fire/alarms/stream（或实际API前缀）关闭 proxy_buffering，并确保读取超时大于心跳间隔。代理不可用时不影响轮询。
- 不调整TCP协议确认顺序、事件去重、119上游同步周期或数据权限。3秒为前台正常运行下的查询间隔，不是端到端硬时限；数据库、网络、浏览器后台节流都会增加延迟。

验证：tools/device-capture/verify_project.py 的隔离MySQL与本机TCP测试覆盖提交后通知、晚期事务回滚不通知及网关范围；tests/fire/alarm-refresh.browser.cjs 使用实际Vue和可控HTTP/SSE夹具验证慢资源隔离、推送、轮询、错误恢复和离页清理，不代表真实设备完整部署验收。部署需重启新版后端并更新前端，当前未强制重启运行中的服务。

SSE断线修复（2026-10-23）：写入失败后仅移除订阅，由Servlet容器完成错误处理，不再重复调用complete；超时与关闭采用一次性终止状态。AsyncRequestNotUsableException单独结束处理，不向text/event-stream响应写入JSON。单个连接关闭异常不会终止推送调度，3秒轮询仍保留。
