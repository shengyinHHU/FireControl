# 短信服务接口调用说明

版本：1.0，2026-11-11。面向所有调用本项目短信服务的程序和 Postman 用户。

你只需要管理员提供 **API 根地址、短信服务账号、密码**。不需要登记项目、不需要平台 SPID、authCode、authKey，也不需要计算 sign。短信平台参数和签名计算由本服务负责。

## 1. 最短调用流程

1. `POST /fire/sms/open/token`，用账号、密码换取 Token。
2. `POST /fire/sms/open/send`，带上 Token、唯一 requestId、手机号数组和短信正文。
3. `GET /fire/sms/open/requests/{requestId}`，查询本账号该次提交结果。

下文以 `http://localhost:8080` 为 API 根地址。部署后改为实际地址，推荐 HTTPS。例如前端 Nginx 若将 `/prod-api/` 转发到后端，则根地址填 `https://实际域名/prod-api`；直接访问后端则填 `https://后端域名或IP:端口`。根地址不要以 `/` 结尾，也不要重复附加 `/fire/sms/open`。前端网页地址不一定是 API 地址。

专用账号由管理员在若依创建，仅绑定“短信接口调用者”角色。这里使用独立服务登录入口，内部复用若依密码校验、错误锁定、登录日志和 Redis Token；**普通 `/login` 获得的 Token 不能替代本入口 Token**，管理员账号也不能用于本入口。

## 2. Postman 直接操作

导入同目录的 `FireControl-SMS.postman_collection.json` 和 `FireControl-SMS.postman_environment.json`，然后选择导入的环境。

在环境变量的本地值中填写：

| 变量 | 填写内容 |
| --- | --- |
| baseUrl | 管理员提供的 API 根地址 |
| username | 短信服务账号，如 sms_api |
| password | 管理员提供的密码 |
| mobiles | 一个或多个真实手机号，英文逗号分隔；初始留空防止误发 |
| content | 短信正文，不加单位签名 |
| bizId | 可选，自己的业务流水号，不用于去重 |
| requestId | 第一次可留空；发送脚本会生成并保存一个小写 UUID |
| token | 无需手填，登录成功自动保存 |

按顺序执行集合中的“01 获取 Token”“02 发送短信”“03 查询结果”。发送成功后先看 `data.taskStatus`；`code=200` 只表示服务已处理请求，不能单凭它判断短信已送达。

**每发送一条新的业务短信，先清空环境变量 requestId，再执行“02 发送短信”。同一次短信的重试或查询保留原 requestId。** 脚本故意不会每次点击 Send 都生成新编号；这样连续点击不会重复发短信。只修改 content 或 mobiles 而不换 requestId，会得到 409。

默认手机号为空时发送脚本会报错并阻止请求，填好真实号码再发送。不要直接运行整个集合来试探服务，因为集合中的发送请求会发送真实短信。密码和 Token 只保存在自己的环境本地值中，不要导出含凭据的环境文件给其他人。

脚本通过 `pm.environment.set` 保存 Token 和 requestId，符合 [Postman 变量使用说明](https://learning.postman.com/latest-v-12/docs/tests-and-scripts/write-scripts/postman-sandbox-reference/pm-variables)。

## 3. 获取 Token

```http
POST {{baseUrl}}/fire/sms/open/token
Content-Type: application/json
```

```json
{"username":"sms_api","password":"填写账号密码"}
```

只接受 username、password 两个字段。用户名长度 2～20，密码长度 5～20，与当前项目若依限制保持一致。此接口不需要图形验证码，仅允许有效的短信专用服务账号使用。默认同一直接连接来源 IP 每自然分钟最多请求 30 次；连续 5 次密码错误，若依默认锁定 10 分钟（以实际部署配置为准）。

成功示例：

```json
{"code":200,"msg":"操作成功","token":"返回的Token","tokenType":"Bearer","expiresIn":1800}
```

token 在响应顶层。后续请求头为 `Authorization: Bearer 返回的Token`，Bearer 后一个空格。expiresIn 单位为秒，由部署的 token.expireTime 决定，默认 1800。若依在活跃访问且剩余时间不足 20 分钟时自动延长 Redis 会话；应以 HTTP 401 判断需要重新获取 Token。账号停用、撤权、角色停用或重置密码后，旧 Token 会在下次调用时被拒绝。

Token 可复用，不要每发一条短信就登录一次。此版本未提供独立 refreshToken 接口；401 后重新获取 Token 即可。

## 4. 提交短信

```http
POST {{baseUrl}}/fire/sms/open/send
Authorization: Bearer {{token}}
Content-Type: application/json
```

```json
{
  "requestId":"5b93fa88-e117-4ff6-a43c-970a517f35aa",
  "mobiles":["13800000001"],
  "content":"您好，请及时处理消防巡查事项。",
  "bizId":"NOTICE-20261111-0001"
}
```

示例手机号仅说明格式，实际发送请改为自己的收件手机号。

| 字段 | 必填 | 类型 / 要求 |
| --- | --- | --- |
| requestId | 是 | 小写 UUID，36 字符；调用方为一次发送意图生成并持久保存 |
| mobiles | 是 | 字符串数组，默认每次 1～10 个大陆 11 位手机号；不允许重复、空格、+86、座机 |
| content | 是 | 非空原始正文；不要 URL 编码，不要加单位签名 |
| bizId | 否 | 最长 100 个 UTF-16 字符的业务编号，省略与空字符串等价；不负责去重 |

不接受表单、逗号字符串 mobiles 或额外的 spid、sign、signature 等字段。默认短信“固定签名+正文”总长度最多 1000 个 UTF-16 字符；中文常用字通常占 1，部分 emoji 占 2。这个数值是本服务校验上限，不代表运营商单条计费长度，也不保证任意正文都能通过平台审核。

当前固定签名为 `【大厂街道办事处】`，由管理员配置；服务自动添加到正文前。实际接收内容例如 `【大厂街道办事处】您好，请及时处理消防巡查事项。`。

成功处理示例（字段值示意）：

```json
{
  "code":200,
  "msg":"操作成功",
  "data":{
    "recordId":"123",
    "requestId":"5b93fa88-e117-4ff6-a43c-970a517f35aa",
    "recipientType":"external",
    "mobiles":["13800000001"],
    "content":"【大厂街道办事处】您好，请及时处理消防巡查事项。",
    "recipientName":"接口收件人",
    "sourceName":"短信接口 / sms_api",
    "taskStatus":"submitted",
    "deliveryStatus":"unconfirmed",
    "platformCode":"1",
    "resultText":"短信已提交平台，送达情况以手机或回执为准",
    "platformTaskId":"平台任务编号",
    "acceptedPhones":["13800000001"],
    "bizId":"NOTICE-20261111-0001",
    "createTime":"2026-11-11 20:00:00"
  }
}
```

recordId 按字符串使用，以免 JavaScript 大整数精度丢失。mobiles / acceptedPhones 数组顺序不作承诺。platformCode、platformTaskId、resultText 是诊断信息，业务分支应主要使用 taskStatus。createTime 是数据库格式化时间；推荐部署数据库与应用统一为 Asia/Shanghai。

## 5. 查询一次提交

```http
GET {{baseUrl}}/fire/sms/open/requests/5b93fa88-e117-4ff6-a43c-970a517f35aa
Authorization: Bearer {{token}}
```

无请求体，返回结构与发送的 data 相同。仅能查询当前账号经开放接口提交的短信；其他账号和人工联系人的短信记录均不可查询，统一返回 404。接口不提供全局列表。

查询读取本服务持久化的提交记录，不会重新发送，也不会实时请求运营商送达回执。长时间 pending（超过 60 秒）的记录查询时显示 unknown，需核对平台记录或手机情况。

## 6. 结果状态

| taskStatus | 含义 | 调用方处理 |
| --- | --- | --- |
| submitted | 平台已受理全部号码 | 记录结果；不能直接当作手机已收到 |
| partial | 平台仅受理部分号码 | 查看 acceptedPhones；核对情况，不能把整个批次直接换编号重发 |
| failed | 平台明确拒绝 | 查看 resultText；排除原因后人工决定是否生成新 requestId |
| pending | 已在本服务落库，原请求仍处理中 | 等几秒后查询同一个 requestId |
| unknown | 超时、响应异常或发送后落库异常，结果无法可靠确认 | 保留原 requestId，先查询并核对平台 / 手机；不要自动换编号重发 |

deliveryStatus 当前固定为 unconfirmed：本版本尚未接入运营商送达回执。

## 7. 去重、限额和重试

去重范围为“账号 + requestId”。同账号、相同 requestId、相同正文 / 手机号集合 / bizId 会返回原记录，不再次发送、不再次扣额度；手机号数组换序不影响。相同编号更改内容返回 HTTP 409。不同账号的同一 requestId 互不影响。bizId 不承担去重，相同 bizId 配不同 requestId 会分别发送。

**调用前持久化 requestId 和完整请求体**。网络超时后先按原编号查询；若查询 404，可以用完全相同的请求体和原编号再次 POST，数据库唯一键会阻止重复提交。即使收到 500 也要沿用这一规则。不要删除历史提交记录来“恢复额度”，这会损坏去重保证。

HTTP 客户端建议超时 45 秒以上；本服务到平台的请求超时为 30 秒。禁止 SDK、网关、任务队列自动生成新 requestId 重试。

默认每账号每自然分钟最多 **30 个收件号码**、每上海自然日最多 **500 个收件号码**；这些是服务限额，不是付费短信分段计数。10 个号码一次提交消耗 10 个额度。额度与提交记录在同一数据库事务中预留，失败或未知结果也消耗额度，重复提交不重复计数。多个后端实例共享数据库额度。具体限额以管理员配置为准。

HTTP 429 带 Retry-After（秒）；等待后沿用原 requestId。HTTP 401 时重新登录，然后用原 requestId 查询或原样提交。HTTP 403 应由管理员检查账号角色，不要反复登录。HTTP 503 说明服务配置、数据库 / Redis 或短信平台配置未就绪；先查询已有记录（若服务整体关闭需联系管理员）。

## 8. HTTP 状态和错误体

错误示例：`{"code":409,"msg":"该提交编号已用于其他内容，请使用新的requestId"}`。开放接口使用真实 HTTP 状态码，成功为 200。

| HTTP | 常见原因 |
| --- | --- |
| 400 | JSON、字段类型、手机号、UUID 或内容长度不符合要求 |
| 401 | Token 缺失 / 过期 / 密码重置，或服务登录失败、锁定、未开通 |
| 403 | 账号 / 角色已停用、权限不符合要求，或可选来源 IP 规则拒绝 |
| 404 | 本账号没有该开放接口提交记录 |
| 409 | 同一个 requestId 使用了不同内容 |
| 429 | 发送额度或获取 Token 频率超限；读取 Retry-After |
| 500 | 结果暂时不可靠，保留原编号先查询 |
| 503 | 开放服务未启用、配置无效或依赖暂不可用 |

平台明确拒绝时，HTTP 200 + data.taskStatus=failed，不能只看 HTTP 是否成功。反向代理自身产生的 413/502/504 可能不是本服务 JSON，也需要按原编号查询后再决定。

## 9. cURL 示例

以下使用 Bash 语法。Windows PowerShell 使用 `curl.exe`，或直接使用 Postman；切勿将实际密码提交到代码仓库。

```bash
curl -X POST 'https://你的API根地址/fire/sms/open/token' \
  -H 'Content-Type: application/json' \
  --data '{"username":"sms_api","password":"填写账号密码"}'

curl -X POST 'https://你的API根地址/fire/sms/open/send' \
  -H 'Authorization: Bearer 填写Token' \
  -H 'Content-Type: application/json' \
  --data '{"requestId":"5b93fa88-e117-4ff6-a43c-970a517f35aa","mobiles":["填写真实手机号"],"content":"接口测试","bizId":"test-001"}'

curl 'https://你的API根地址/fire/sms/open/requests/5b93fa88-e117-4ff6-a43c-970a517f35aa' \
  -H 'Authorization: Bearer 填写Token'
```

## 10. Python 示例客户端

同目录 `sms_client.py` 只依赖 Python 3 标准库，支持获取 Token、发送和查询。环境变量配置 API 地址、账号和密码；首次发送会在请求文件中生成并保存 requestId，再发 HTTP 请求，重复执行同一文件不会另发一条。

PowerShell：

```powershell
$env:SMS_BASE_URL='https://实际API根地址'
$env:SMS_USERNAME='sms_api'
$env:SMS_PASSWORD='填写账号密码'
python .\sms_client.py prepare .\request-001.json --mobile 填写真实手机号 --content '接口测试' --biz-id 'test-001'
# 先打开 request-001.json 确认内容，再真正提交
python .\sms_client.py send .\request-001.json
python .\sms_client.py query .\request-001.json
```

prepare 只写文件，不调用服务；已存在的文件禁止覆盖。send / query 会先获取 Token；HTTP 401 时最多重新登录一次并沿用原编号。网络超时、500 或未知状态不自动重发。请求文件含手机号和正文，应由调用方妥善保存。

## 11. 常见问题

- **需要自己计算 sign 吗？** 不需要，只传账号密码获取 Token；手机号和正文按 JSON 原文填写。
- **可以使用任意单位短信签名吗？** 当前接口使用服务端固定已配置签名，调用方不能覆盖。
- **多个系统是否需要登记项目？** 不需要。可以共用一个账号（共享额度和查询范围）；也可由管理员为不同系统分别创建账号，便于隔离和停用。
- **Postman 返回 401？** 先检查选中环境、baseUrl、专用账号密码，再执行获取 Token。不要用普通管理后台 Token。
- **反复发送为什么返回同一记录？** 环境中的 requestId 没有清空；这是防重复设计。新的发送意图才清空并生成新编号。
- **200 但手机没收到？** 检查 taskStatus、acceptedPhones 和 resultText；submitted 代表受理，最终收到需以手机或运营商回执核实。
- **能取消已经受理的短信吗？** 本接口不提供取消能力。
