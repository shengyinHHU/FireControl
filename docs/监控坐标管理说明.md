# 监控坐标管理

入口：**视频监控 → 坐标维护**。视频预览仍使用原有真实目录与播放器。

## 当前初始化结果

2026-11-02，已在当前配置的 `dachang` 执行增量建表，并从真实天翼视联账号完整同步 **65个目录、736台监控**。初始736台均未填写坐标，没有推断或填充位置，没有修改查岗岗位、绑定和记录。

首次调查表：`outputs/video-catalog/监控坐标调查表.xlsx`；同步记录：`outputs/video-catalog/initial-sync.json`。这是初始化时的快照，之后请以页面最新台账为准。

## 使用流程

1. 点击“同步监控目录”，等待完整同步成功。后台读取全部目录与设备分页，失败不会提交不完整清单，已有坐标始终保留。同步发现的设备数与本地保留的历史台账数可能不同；平台未返回的旧设备不自动删除。
2. 点击“导出未定位”，导出当前目录及搜索条件下尚无坐标的全部监控；“导出当前筛选”包含全部符合条件的数据，不限当前页。
3. 在Excel黄色列填写经度、纬度、坐标系、安装位置和调查备注。设备编码按文本保存，不要修改视频来源或坐标版本。新设备坐标为空；经纬度都空时跳过，不清除已有数据。
4. 现场采集时确认坐标系：高德GCJ-02、GPS WGS84、百度BD-09。未知坐标系先核实。后两者会转换为GCJ-02并保留原值；本地转换为近似计算，实际点位仍需现场核验。
5. 点击“导入坐标”，默认仅补空坐标。选择文件后检查预检结果，再确认更新；错误、重复编码、未知设备、版本冲突行不写入。允许覆盖模式会列出原坐标和新坐标。
6. 导入后在地图“摄像头”图层显示有效点位，点击点位查看真实监控资料和视频。无坐标设备仍在台账中；图层最多显示5000个有效点位并明确提示截断。
7. 单条编辑可修正坐标或将现场核验后的位置设为“已核验”。Excel导入的新位置保持“待核验”；没有位置变化的往返导入不降级已核验状态。

导入预检有效期2小时并绑定上传用户。提交再次检查版本；提交期间任一可更新行发生冲突，则本次写入全部回滚，需重新预检。已完成批次重试返回原结果，不重复修改。批次和逐行前后值存储于数据库，页面可下载处理报告。

## 部署

- 迁移：`SQL/fire_video_catalog.sql`，在 `dachang` 可重复执行。新增5张视频台账/同步/导入表及4个按钮权限，不覆盖已有业务记录。
- 后端：重新启动最新 `ruoyi-admin`。前端：`npm run build:prod` 后部署 `RuoYi-Vue3/dist`。当前未发现正在运行的项目后端进程，因此没有停止或替换IDE进程。
- 管理员默认可操作。普通用户须同时满足现有视频账号 `allowed-user-ids` 限制、`fire:video:list` 和对应 `fire:video:sync/export/import/edit` 权限；播放仍需 `fire:video:preview`，对讲仍需 `fire:video:talk`。新增按钮权限不会自动授予既有角色。
- 账号变更后使用不同来源标识，旧账号台账不会暴露给新账号。目录与名称不自动关联业务场所。
- 同步最大10分钟、5000个目录、50000台设备；超限明确失败并保留原数据。服务中断留下的运行状态15分钟后允许重新启动同步。

接口均位于 `/fire/video/catalog`：查询、目录、地图、单条详情、同步、导出、导入预检/确认及单条坐标编辑。

## 验证

- `python tools/video/verify_catalog.py`：隔离MySQL，验证完整分页、目录递归、去重、Excel文本编码/空值、坐标转换、账号和批次隔离、幂等、审计和事务冲突；不访问真实业务库或平台。
- `RuoYi-Vue3/tests/fire/video-coordinates.browser.cjs`：真实Vue页面，HTTP及地图SDK受控样本；验证上传预检、导出范围、编辑、错误恢复、窄屏、键盘和地图播放器联动。
- `python tools/video/initialize_catalog.py`：显式连接当前业务数据库和视频平台，完整同步并导出未定位调查表。部署新环境时先执行迁移再按需使用；不会修改已填坐标。

浏览器样本不代表现场码流播放验收；现有H.265/G.711等播放器能力及限制保持不变。
