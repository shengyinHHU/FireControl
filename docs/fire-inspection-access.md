# 查岗管理部署与使用

## 启用步骤

1. 在现有 `dachang` 数据库导入 `SQL/fire_inspection.sql`。脚本新增岗位、岗位摄像头绑定、查岗记录三张表和三个权限项；不导入模拟岗位，不修改已有机构与视频数据。
2. 重新启动最新 `ruoyi-admin`，重新构建并部署前端。开发环境重新运行前端即可。
3. 管理员进入“查岗管理 → 岗位配置 → 新增岗位”。填写名称、可选所属机构，从“视频监控”目录选择摄像头，选择一台默认摄像头并保存。
4. 在“岗位查岗”或大屏查岗区域打开岗位。人工查看画面、按需对讲、选择在岗/脱岗/无法判断，填写说明、按需抓拍，保存记录。
5. “查岗记录”中按时间、岗位/机构/查岗人、结论查询。历史抓拍与历史名称保留；“查看当前岗位视频”打开当前绑定，不冒充历史录像。

本次没有向业务数据库执行 SQL，也没有自动绑定全部摄像头。只有配置并启用的岗位会出现在大屏查岗区。一个岗位支持 1–12 台摄像头；相同摄像头可用于不同岗位。岗位排序数字越小越靠前。解绑和停用保留历史，暂不提供物理删除。

## 角色与数据范围

超级管理员可直接使用。其他角色按需分配：

| 权限 | 用途 |
|---|---|
| `fire:inspections:list` | 岗位、记录、历史抓拍查看 |
| `fire:inspections:edit` | 新增和配置岗位，需同时有查看权限 |
| `fire:inspections:add` | 新增查岗记录，需同时有查看权限 |
| `fire:video:list` | 从既有视频目录选择摄像头 |
| `fire:video:preview` | 播放岗位摄像头 |
| `fire:video:talk` | 使用已有语音对讲 |
| `fire:places:list` | 搜索所属机构，可不关联机构 |

真实视频账号访问仍受现有 `fire.video.allowed-user-ids` 配置约束。岗位和查岗记录复用若依部门/本人数据范围；新岗位归属创建人及其部门。记录继承岗位数据范围。角色权限变更后重新登录。

## 抓拍文件

默认保存到 `ruoyi.profile` 的同级目录：原目录名加 `-inspection-private`，例如 `D:/ruoyi/uploadPath` 对应 `D:/ruoyi/uploadPath-inspection-private`。目录自动创建，运行账号须有写入权限。不能放在公开的 `profile` 内。

可在已有配置的 `fire` 节点下合并以下配置（不要重复创建同名 `fire` 节点）：

```yaml
fire:
  inspection:
    evidence-path: D:/ruoyi/inspection-private
```

证据通过登录鉴权接口读取，按记录的数据权限检查，不能匿名通过静态路径访问。仅接受最大5MB、4096像素以内的JPEG/PNG并转为JPEG。前端从当前视频画面抓取；文件写入失败不保存记录，数据库事务失败清理文件。备份时同时备份三张表和该私有目录；更换目录需迁移旧文件。

## 边界与验证

这是人工视频查岗，尚未增加排班计划、自动识别在岗、历史录像回放或自动抓拍。直播失败不能判定脱岗，可保存“无法判断”。对讲沿用现有能力与设备限制；普通内网HTTP可管理和保存查岗，采集麦克风仍需HTTPS或localhost。浏览器可提交人工结论与图片，抓拍属于人工留证，不是设备端签名证据。

SQL已在隔离MySQL重复导入；后端验证覆盖真实权限切面、事务、快照、重试去重、停用/解绑和证据隔离。浏览器使用受控接口与画面验证配置/查岗/历史流程，未访问业务数据库或真实摄像头；部署后需用实际账号和摄像头完成现场验收。

## 岗位联系人字段升级

已导入旧版查岗表的环境，请先导入 `SQL/fire_inspection_contact_upgrade.sql`，再重启更新后的后端。全新安装直接使用最新 `SQL/fire_inspection.sql`。升级可重复执行，保留已有岗位和记录；联系人默认为空，可在岗位配置中补填。联系人姓名最多100字，电话最多64字，均为选填，支持手机、固定电话及分机文本，不会自动修改机构联系人。

## 视频监控入口调整

真实视频监控统一位于 `/fire/video`，原模拟视频列表已替换。查岗管理 `/fire/inspections` 只保留岗位与查岗记录；旧地址 `/fire/inspections?tab=video` 自动跳转至新视频页。视频页使用 `fire:video:list` 权限，无须另授予旧模拟摄像头权限 `fire:cameras:list`，仍受原视频账号访问范围约束。本次入口调整无须新增SQL。
